## Legenda de status

- **RESOLVIDA** — quitada por uma Work Order posterior, com evidência objetiva.
- **ABERTA** — permanece sem correção até o fechamento desta sprint.
- **SUPERADA** — o contexto que originou a dívida deixou de existir (ex.: código removido/substituído).
- **NÃO APLICÁVEL** — não representa uma dívida real (ex.: escopo intencionalmente futuro).

Consistente com os relatórios de segurança já registrados nas sprints anteriores (O1.5, O1.13, O1.13.5 sem CRITICAL/HIGH).

## Achados da Validação Funcional #41 (12/08/2026)

Sessão de validação funcional real (backend + frontend + navegador real via Chrome DevTools MCP, `MaisComprasConnection`/`SOMA_DESENV` reais, VPN disponibilizada pelo Product Owner). Encontrados e corrigidos nesta mesma rodada, com reteste funcional confirmando a correção:

1. **DEB-20** (HIGH) — Administrador Sênior real do banco de desenvolvimento tinha apenas 14 das 19 permissões do catálogo (backfill de permissões novas nunca reexecutado desde O1.5). Corrigido via migration; confirmado `19/19` no banco e via `GET /auth/me` real.
2. **DEB-21** (HIGH) — `GET /me/unidades-negocio` sempre recebia o `index.html` do Vite em vez do JSON do backend (rota `/me` nunca esteve no proxy de desenvolvimento) — Seleção de Unidade de Negócio (#3) quebrada para todo usuário em DEV. Corrigido no `vite.config.ts`.
3. **DEB-13 reaberta** (HIGH, antes classificada erroneamente como "SUPERADA/não reproduz") — `GET /fornecedores` retornava `500` (`Invalid column name 'Nome'/'Cnpj'`) para qualquer busca. Corrigido em `FornecedorConfiguration.cs`.
4. **DEB-19** (HIGH, nova) — `GET /api/administracao/centros-custo` retornava `500` sempre (tabela `CENTRO_CUSTO` configurada não existe; a real é `CENTROS_CUSTO`). Corrigido em `appsettings.json` + `SomaCentroCustoReader`.
5. **Escalonamento de escopo administrativo via nome de Perfil** (HIGH) — já corrigido na rodada anterior (ADR-0022); **revalidado nesta sessão em produção real**, com dois atores reais (Administrador Sênior e um Administrador de BU real recém-criado) tentando a autopromoção via UI/API real — ambos corretamente bloqueados (`403 nome_reservado`).
6. **Cross-BU real, positivo e negativo** — validado com dois atores reais e duas Unidades de Negócio reais (`Grupo Soma` e uma nova `BU Teste Gate 41` criada durante a sessão, com catálogo de Perfis auto-seedado confirmado no banco): Administrador Sênior acessou (leitura e escrita) a BU nova com sucesso; o Administrador de BU real recebeu `403 escopo_administrativo_negado` ao tentar o mesmo, mesmo manipulando diretamente a URL da API com o Id da outra BU.

Nenhum dos achados 1–4 é do domínio "escopo administrativo Produto×BU" (ADR-0022) — são bugs de configuração/mapeamento pré-existentes, nunca detectáveis sem uma conexão real ao ambiente (banco, ERP, ou proxy do navegador), e por isso invisíveis a toda a sequência de Gates anteriores, cujas sessões não tinham VPN disponível.

## Reauditoria dos 17 controllers administrativos — ADR-0022 (Gate Final da Onda 1, continuação 12/08/2026)

# Work Order O1.3.3 — Fundação funcional do módulo Gestão de Filiais

Status:
✅ Concluída — encerrada oficialmente em 06/08/2026, com aprovação explícita do Product Owner.

## Objetivo

Implementar a fundação visual (mockada, sem backend/ERP real/persistência) do módulo `administration/branches`, aplicando a regra de cadastro integrado do ERP aprovada na ADR-0020 (item 3): Filial é dado mestre do ERP, nunca criada ou alterada no +Compras — apenas ativada/inativada localmente, com metadados locais opcionais (Descrição +Compras).

## Critérios de aceite

- [x] Vertical Slice `administration/branches` criada seguindo o padrão físico já estabelecido por `administration/profiles`/`administration/users` (`pages/`, `components/`, `hooks/`, `services/`, `types/`, `routes/`, `tests/`).
- [x] Nenhuma ação de criação ou exclusão de Filial em nenhuma tela (dado mestre do ERP).
- [x] Listagem exibe simultaneamente Código CliFor, Nome CliFor (descrição ERP) e Descrição +Compras.
- [x] Tela de edição separa visualmente "Dados do ERP (somente leitura)" de "Dados +Compras (editáveis)", com aviso explícito de que alterações no +Compras não modificam o ERP.
- [x] Ativação/inativação local disponível na listagem e no formulário de edição.
- [x] Rota `/administracao/filiais` registrada em `core/AppRoutes.tsx`; item "Filiais" no menu de `core/AppShell.tsx`.
- [x] Catálogo mockado cobrindo filial ativa sem Descrição +Compras, filial ativa com Descrição +Compras e filial inativa no +Compras.
- [x] Design System: reaproveitamento exclusivo das classes já existentes em `styles.css`, sem novo componente.

## Validações executadas

- `npx tsc -b`: aprovado, 0 erros.
- `npm run build` (`tsc -b && vite build`): aprovado.
- `npm run test` (Vitest): aprovado, 17/17 testes (10 pré-existentes inalterados + 7 novos de `FiliaisPage`).
- Smoke test do `npm run dev`: `/` e `/administracao/filiais` respondem HTTP 200; módulos JS da nova slice resolvem via Vite sem erro de import; rota registrada em `AppRoutes.tsx` e item de menu em `AppShell.tsx` confirmados por análise estática.

## Resultado

Módulo `administration/branches` implantado como fundação visual do domínio Filiais, seguindo integralmente o padrão Vertical Slice (ADR-0020) e a regra de cadastro integrado do ERP (ADR-0020, item 3; Domain Principles, seção "Cadastros Integrados"). Nenhuma regra de negócio, contrato de API real ou persistência foi introduzida — escopo exclusivamente de fundação visual mockada.

## Pendências registradas (não bloqueantes)

- Sem integração com API real, ERP ou persistência — conforme escopo explícito desta etapa.
- Demais domínios de Administração (`cost-centers`, `allocation-units`) permanecem como esqueleto vazio, endereçados por sprints futuras (próxima: O1.3.4).
- Oportunidade de refatoração registrada: `administration/profiles`, `administration/users` e `administration/branches` repetem o mesmo padrão de página/hook/tabela/mock service; avaliar extração para `administration/shared` quando um quarto módulo reforçar a duplicação.
